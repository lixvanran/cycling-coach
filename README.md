# 公路自行车 AI 教练 · Cycling Coach

**本地优先、开源免费、对数据诚实**的公路车训练分析工具。

对标 TrainingPeaks 的核心训练分析能力，Windows 桌面本地运行，数据不出本机。

---

## 一句话说明它是什么

导入 Garmin / Wahoo 的 FIT 文件，得到 TP 同级别的训练负荷分析（CTL/ATL/TSB、功率区间、能量分布），
外加一个基于 359 篇专业资料的中文 AI 教练。

**它不会在你没测 FTP 时假装知道你的 FTP，也不会在数据不足时给你一个看起来很权威的分数。**

---

## 核心原则：缺数据 ≠ 编一个像样的值

这是这个项目和其他"看起来很完整"的工具最大的区别，也是我们花最多力气的地方。

| 场景 | 常见的做法 | 本项目的做法 |
|---|---|---|
| 零训练数据 | 训练负荷显示 `CTL 0.0` | 「还没有带功率的训练记录」 |
| 零数据 readiness | 归一化给个 82 分"极佳" | 算不出就是 `null`，并说明缺哪几个维度 |
| 只有 RPE 的休息日 | 训练负荷维度照常计分 | 识别为"无负荷数据"，不占分数 |
| 数据不足时的目标 TSS | `0`（看起来像"今天免练"） | `null` + 界面显示"目标待定" |
| 只有 2/5 个维度可用 | 归一化出 100 分"极佳" | 封顶 70 分 |
| 没有 FTP | 沿用默认 250W | 用**估算值**算并标记 `用估算=True`，或明确说算不出 |
| 0 训练时打印"今日计划" | 打印空计划 | 打印"无计划"并链接 FTP 输入指引 |

这些不是设计文档里的口号，是 `tools/scan_data_honesty.py` 每次运行机器校验的。

**但要说清楚它覆盖到什么程度** —— 产品有 127 个接口操作（107 条路径），
扫描器实际覆盖 **58 个，约 46%**：

- ✅ 覆盖：无路径参数的 GET（75 个 GET 里的 58 个）
- ❌ **不覆盖：所有 POST / PUT / DELETE** —— 上传、写计划、导入等写操作一律不扫
- ❌ 不覆盖：带路径参数的 GET（17 个，如 `/api/activities/{id}`）
- ❌ 不覆盖：strava / static 等被排除的路径

所以它是**防回归的护栏**，不是全面保证。写操作的诚实性目前靠
逐个 review 和专门的测试保证。

> 这段说明本身是 Verifier 复审逼出来的 —— 我原来写的是"扫 107 个端点"，
> 既和同一份文档里另一处的"58"自相矛盾，也是一个**虚假覆盖率声明**。
> 在一个卖点是"不编造"的项目里，夸自己的检查力度比不检查更糟。

## 快速开始（Windows）

### 前提

- Python 3.11+
- **不需要装 Node.js**（前端已随源码包提供）

### 三步

```bat
:: 1. 解压到短路径（重要：知识库里有长路径名，别放太深）
mkdir C:\cc
:: 把 zip 解压到 C:\cc  —— 用命令提示符解压到 C:\cc，
:: 不要双击 zip 让资源管理器解到"下载"目录（路径会变长，逼近 260 字符上限）

:: 2. 双击 tools\ACCEPTANCE_CHECKLIST.bat
::    它会一步步带你走：装依赖 -> 自检 -> 启动 -> 检查界面
::    每一步都有明确的"通过/停在这里"，出问题会告诉你报告在哪

:: 3. 日常使用就双击 tools\start.bat
```

> ⚠️ **如果你要手动敲命令启动，必须带 `--desktop`**：
>
> ```bat
> python tools\start.py --desktop
> ```
>
> 不带的话会进开发模式，试图启动 Vite —— 而 **Windows 上你没装 Node.js**。
> `start.bat` 会自动加上这个参数，但手动敲时容易漏。

`start.py` 会自动完成：建虚拟环境 → 装后端依赖 → 拉起服务 → 打开浏览器。
**不需要你手动 pip install。**

### 第一次用

1. **先看示例** — 首页有「先看示例」按钮，一键灌入 8 周真实结构的演示数据，
   立刻能看到完整界面长什么样，不用先啃文档。
2. **或者直接导入 FIT** — Garmin / Wahoo 的 `.fit` 文件，拖进去就行。
3. **去「数据 → 数据可信度」** — 那一页会告诉你：哪些数据有、哪些缺、缺的原因、以及每个算法的文献出处。

### 建议顺手填一个 FTP

不填也能用（会用估算值并标明），但填了之后解锁：功率区间、时间在各区间分布、
能量分布（polarization）、以及 AI 引用具体数字时不用再含糊其辞。

## 功能

### 训练数据

- FIT 自动导入（Inbox 文件夹监听 / 手动上传 / 命令行）
- 功率区间、能量分布、训练负荷（CTL/ATL/TSB/ramp rate）
- 训练计划与实际对比、周期化（Phases）
- 日历视图、趋势、两条训练对比
- 手记 / 日记

### AI 教练

- 中文对话，基于 **359 篇**专业资料（RAG）
- 回答会引用具体文献出处
- 上下文注入你**真实**的训练数据——没有的数据会明确告诉 AI"无数据"，
  而不是塞一个 0 让它照着编

### 数据可信度（V0.9.0 新增）

这是我们认为最被低估的功能。`/数据/数据可信度` 会告诉你：

- 每个数据维度的覆盖率
- 缺失的具体原因
- 每个指标的算法出处（文献链接）
- 产品在"数据不足"时的明确策略

**一个不敢告诉你哪里不完整的数据工具，不值得信任。**

## 项目结构

```
cycling_coach/
├── core/
│   ├── metrics/         # 指标计算（功率/心率/区间/训练负荷）
│   ├── pmc.py           # PMC 模型 (CTL/ATL/TSB)
│   ├── coaching/        # readiness / 建议生成
│   ├── services/        # 领域服务
│   └── reports/         # 周报 PDF
├── api/routers/         # 26 个路由模块, 127 个接口操作 (107 条路径)
├── data/sqlite/         # 存储层
└── static/              # 前端构建产物 (随包提供, 不需要 Node.js)

apps/web/                # 前端源码 (React + TypeScript + Vite)
kb_source/markdown/      # 知识库原文 (359 篇 .md + LICENSE/NOTICE = 361 个文件)
tools/                   # 启动/打包/校验脚本
tests/                   # 30 个测试文件
```

## 开发

```bash
# 后端
.venv/bin/python -m pytest tests/ -q

# 前端
cd apps/web && npm run dev      # 开发模式
cd apps/web && npm run build    # 构建到 cycling_coach/static/

# 数据诚实性校验（每次改动后都该跑）
.venv/bin/python tools/scan_data_honesty.py    # 扫 58 个端点的零数据行为 (约占 46%)
.venv/bin/python tools/check_contract_shapes.py # 契约形状

# 打包 Windows 源码包
.venv/bin/python tools/package_source.py /path/to/output.zip
```

### 打包护栏

`tools/package_source.py` 带硬护栏，少一样东西就直接中止打包：

- `cycling_coach/static/index.html` 缺失 → 中止（否则用户打开是白页）
- 知识库文件数 < 100 → 中止（否则 AI 检索没有资料）

这两个坑都真实踩过：前端构建产物被 `.gitignore` 排除导致打包漏掉；
知识库 359 个长路径文件在 `git ls-files` 逐行读取时被静默丢弃。

## 已知限制

说清楚比藏着好。

- **仅 Windows 桌面优先**。macOS / Linux 未做正式验证。
- **AI 调用需要你自己的 MiniMax API Key**，不开就是纯本地功能（仍然完全可用）。
- **不做云端同步、社交、多车手管理**。这是刻意的取舍，不是遗漏。
- **原生 Windows 行为无法在 Linux 上验证**，需要你在真机上跑一遍。
- 内置训练器（TP Virtual）类功能不在范围内。
